# Clip events and notifies

HORO-472 uses the existing clip cursor, integer residual, state/action controls and graph Commit. Clip events are separate from state-machine events and action completion results. There is no notify clock, callback service or gameplay object ownership in Animation.

## Immutable authoring

`AnimationClipData::eventSchemas` owns exact semantic type/revision declarations. Each event owns a stable clip-local marker ID, bounded display name, exact clip-local time, optional positive duration and a fixed eight-field value map. Values are boolean, signed/unsigned integer, finite double/vector or valid asset ID. Fields use stable IDs; undeclared, duplicate, missing required, wrong-type and nondefault hidden fields are rejected. Optional unsigned allowlists let an adjacent cook validate registered finite values such as a foot-contact slot without parsing event names at runtime. The owning adapter supplies those schemas and IDs; Animation does not invent a gameplay registry.

Metadata is copied and validated with the actual clip publication/generation. Empty metadata remains compatible with existing clip contracts; there is no new persisted clip codec or GraphSource schema. Compression keeps metadata from the same source publication. Changing event semantics requires a new clip generation and, when field meaning changes, a new schema revision. A higher-level adapter must serialize this metadata in its own cooked format explicitly.

## Directed interval semantics

Point traversal is `(old,new]` forward and `[new,old)` reverse. The first actual travelled origin is included once when `fireOnActivation` is true; zero-delta sampling or a terminal hold creates no activation point. Reverse events require `fireInReverse`. Region boundaries use absolute clip sample times while the sole existing cursor remains region-relative.

Durations own `[start,end)`. Forward entry begins and forward arrival at end closes. Reverse entry below end begins; reverse arrival at start still owns that boundary until departure below it. Direction changes reconcile that exact directed occupancy. Each End references its delivered Begin serial; suppressed or unvisited events cannot create an unmatched End. Coincident hits sort End, Begin, Point, then stable marker ID. Each player preserves chronological segment order; player invocation order is the existing canonical execution order.

`TraceRegionPrepared` first admits the complete original interval, then splits it through the same checked traversal provider into caller-owned segments. Its returned full cursor, sample, direction, terminal state and boundary count are the exact original traversal result. Loop seams explicitly close cropped duration windows and enter the opposite region edge. Forward arrival at the end includes that edge and the next origin once, even when delta ends exactly there; reverse departure from zero enters the previous end, while reverse arrival at zero does not repeat it. PingPong turns are continuous and their point is emitted only on arrival. Checked cyclic cursor departures/arrivals also carry cycle-identity deltas, so PingPong cycle ordinals advance without inventing a wrap clock or treating its turn as a discontinuity. Skipped multiple passes are visited in bounded segments; host time dropped before Evaluate is not synthesized.

Sync alignment is relocation, not travel. Only the actual adapted follower advance produces crossings. Relocation, including a zero-travel alignment during a paused leader change, closes a prior delivered duration at its prior held sample and resume occupancy at the actual new interval origin; it never emits points for the skipped alignment interval. Existing authored sync event policy selects leaders/all/suppression. State transition policy independently selects source/destination/highest contribution/all/suppression; ties choose source. Generic pose-layer masks do not infer gameplay policy. A zero state contribution is ineligible.

Actions use every real consumed section interval, including leftovers into another section or queued action. A held/zero-rate active action explicitly stages its real zero-travel cursor so it is not confused with an inactive player; it retains duration ownership without replaying activation. Exact loop handoff publishes the crossed loop entry and its duration occupancy immediately, even when no remaining travelled segment follows in that tick. Directed action-loop ordinals survive held seams and aborted attempts. Section handoff, loop repetition, cancellation, interruption and terminal stop close durations through the existing action authority. Lifecycle closure reasons carry the actual held sample and current real evaluation tick; they do not pretend the authored endpoint was traversed.

## Publication, ownership and migration

Create preallocates candidate state, duration ownership, traversal/hit scratch, both immutable publication slots and cold typed owner queues. Full fixed payload bytes are charged in every retained logical element category, alongside the existing storage budget (allocator/control-block overhead is outside that byte contract). Complete work, crossing, occurrence and per-consumer queue bounds are checked before publication. Serial exhaustion or backpressure rejects the complete attempt; cursors, serials, windows and queue prefixes remain committed. Abort and cancelled Commit preserve exact retry identity. Commit publishes events with the same pose, parameters, actions and controls. No hot allocation, I/O or native callback is used.

Create adapters must forward their actual `AnimationEvaluationDomain` from the component. Presentation and EditorPreview allocate no authoritative notify workspace, and attaching authoritative subscriptions to either domain is rejected. Unknown domains fail. The default Count/unspecified value preserves event-empty legacy callers only. Actual event metadata or subscriptions require an explicit real component domain; reload into event metadata without it fails while retaining the old instance.

`CopyClipEvents` reads an immutable resident pose-publication slot without consumption. Repeated reads retain identical occurrence IDs. IDs include instance incarnation, clip revision, marker, original player, candidate-stable serial, directed loop ordinal, phase and actual tick. Adjacent systems deduplicate this exact ID rather than marker name or dense frame index. Copied fixed payloads remain valid after clip or instance retirement.

`DrainClipEvents` is owner-thread-only and consumes a bounded prefix once. A pending candidate forbids draining because Commit's preflighted capacity must remain stable. Shutdown closes new evaluation, permits draining previously committed values and creates no fabricated terminal-tick notifies. Duration ownership is scoped to the instance generation: the owner must revoke all outstanding windows on Shutdown/destruction or replacement. End records handle ordinary in-generation closures; a revoked producer generation never needs fake endpoint travel. Foreign consumers/threads fail without modifying output counts.

Replacement requires no pending evaluation and no unread subscribed queue values. The owner drains first, then invokes normal transactional Replace. A failed Replace preserves every old pose, cursor, window, queue and identity; successful Replace revokes the old generation atomically. There is no silent queue discard or forced duplicate. Retained old value copies remain safe, while old pose handles obey the existing two-slot/generation fence.

The narrow event payload vocabulary deliberately avoids unbounded generic VariantMap storage and dependencies on Extensions/Cinematic. An adapter requiring another field kind must extend the closed schema explicitly and qualify serialization, validation and retained-byte accounting; opaque pointers or borrowed payload leases are not admitted.
