# UI Canvas device preview and visual layout authoring

The workspace controller derives `UiCanvasPreview` from the canonical `UiCanvasDocument` on source or device/orientation changes. It creates an isolated bounded retained tree, resolves the existing Runtime UI canvas policy from physical resolution, rational DPI and safe-area evidence, selects authored responsive alternatives, resolves the actual host-selected style registry/theme and runs `UiDeclarativeLayoutEvaluator` through `UiLayoutEngine`. The view draws copied content bounds, device/safe-content outlines, rulers and guides. This is layout inspection, not a backend pixel-rendering or asset-texture preview claim. Missing required intrinsic providers and unsupported world-space resolution return their original typed failures and remove stale interaction geometry.

Desktop (1920x1080, 1x), phone (1170x2532, 3x) and tablet (2048x2732, 2x) evidence are explicit preview presets, with clockwise orientation and rotated safe-area insets. Device, orientation, zoom, pan, tool, grid and up to eight guides per axis are workspace values. They never enter serialization, dirty state or undo history. Pan/zoom/tool/guide changes reuse evaluated layout; source/device/orientation and style resource publication/theme changes re-evaluate it outside drawing. Computed width/height/padding are projected after responsive bases through `ProjectUiThemeSurface`, which delegates to the same surface projection used by `UiThemeRuntime`. Missing style capabilities or invalid references fail explicitly; the preview never creates a substitute registry.

Selection uses the actual evaluated bounds in reverse paint hierarchy order. Move, resize and anchor tools operate on absolute layout elements; flow elements require an explicit positioning change in the existing inspector. Logical deltas use the scale captured at gesture start, and preview-scale/source/selection/device changes cancel the gesture. Escape, host input cancellation, project reset and document disappearance also cancel. Shift-click adds a vertical guide; Ctrl-Shift-click adds a horizontal guide; Clear guides removes them. Middle-drag pans. Grid and nearest-guide snapping happen in canvas logical coordinates; nested elements retain their authored parent-relative offsets. Resize authors content width/height, preserving box-model fields. Anchors use normalized Runtime UI units derived from parent content extents.

A completed drag submits one `UiCanvasCommitLayout` typed intent. The controller checks the document instance/state and selection, prepares a complete canonical presentation preserving unrelated style/control/accessibility values, then calls `UiCanvasDocument::Execute`. Semantic history supplies undo/redo; reload/close fences reject old gestures. Preview failure does not change the document.

## Additive runtime API

`UiPresentationProfileTable::CreateForAuthoring(document, tree, canvas)` is the source-authoring ingress. It verifies exact document/revision, canvas root, complete source subtree membership and parent relationships before using the same canonical bounded table validation, selection and layout application as runtime `Create`. The existing cooked-generation ingress and all existing callers remain unchanged. Editors migrate to the source ingress instead of fabricating a cooked Assets closure. The existing public header remains owned by its original CMake target; the consumer contract covers the additive declaration.

`ProjectUiThemeSurface` is an additive copied authoring projection over an actual computed publication. Its existing owning header/target does not change. It delegates to the runtime theme projection, preserves typed failure, and leaves inputs untouched. Existing runtime callers retain their original path; the editor calls this public ingress rather than including private Runtime UI helpers. Public consumer and actual selected-theme regression coverage exercise both additive ingresses.
