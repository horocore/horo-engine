# Prefab override layers

Prefab resolution uses one canonical source resolver. It resolves the full immediate parent of a variant before applying `PrefabComposition::variantOverrides`. It resolves each referenced nested source before applying `NestedPrefabPlacement::valueOverrides` and mounting that occurrence. A containing variant can then override the nested stable address. The existing Scene-instance delta applies last. The supported algebra is whole-transform assignment, registered typed property assignment, and registered component Add/Remove (replacement is one removal plus one fresh addition). Collection-element edits remain outside this algebra.

Layers use the existing `PrefabValueOverrideSet`: stable local scopes, component type/occurrence/property IDs, source preconditions, schema digest, and owned conflicts/orphans. Source documents without layers keep their existing canonical encoding. Every nonempty layer must identify the exact immediate referenced source and match the edge's `authoredAgainst` revision. Empty layers are omitted. Unknown schemas, permissions or migration behavior are never inferred from display names or opaque payloads.

Hosts may supply a shared immutable `PrefabValueSchemaSnapshot` when building the source resolver or capturing hierarchy sources. Workspace composition copies an explicitly registered snapshot, if supplied. `PrefabSceneCookRequest::overrideSchemas` carries the same explicit authority into source expansion and outer Scene-instance value resolution. Core transform-only deltas work without project schemas. Typed project properties and component topology require their real validating schema/permission snapshot; absent metadata retains orphan evidence and prevents runtime publication.

`PrefabDocumentSession::ExecuteLayer` prepares a value or component command through the existing resolver and accepts the complete source change through the existing document fence and semantic history. A null placement selects the variant layer; otherwise the exact existing placement ID selects a nested layer. Apply/Revert/Rebase, Undo/Redo, source-save and preview retirement share this document authority. Rebase may deliberately persist owned conflict/orphan evidence, but it cannot publish a runtime candidate. Explicit assignment or revert resolves the selected intent. A stale fence, cancelled preparation, allocation failure or rejected history admission preserves the prior source/revision/history.

The default graph capture mode is `RequireExact`. Authoring may explicitly request `PreserveLayerRebase` to retain both authored and actual target revisions. `ResolveOverrides` returns no effective hierarchy while any inspected layer is unresolved or any captured semantic edge is stale. Its layer evidence is the canonical inspected prefix; downstream original layers remain intact in `Sources()` when their effective input is unavailable. The strict `Resolve` wrapper, caches, preview-stage activation and cook path never treat authoring capture permission as runtime permission. A real document transaction must accept updated edge/layer revisions before strict resolution can succeed.

Record/conflict/orphan arrays normalize by semantic stable identity. Contradictory or duplicate targets are rejected; no last-writer-wins behavior exists. Parsing permits only the arrival order of complete records to differ. Canonical numeric and string spelling, metadata, object fields, per-row field spelling, unknown-field rejection and duplicate-key rejection remain strict in the override codec. The source canonical-input matcher likewise changes only validated override-array ordering in validation scratch. `SerializeCanonical` and the existing allocation-safe canonical writer remain the sole source output authority. Cook keeps the actual raw input digest as provenance and derives the semantic prefab source revision from the canonical document encoding.

A preflight checks the complete combined graph for cycles, current profile bounds, actual repeated object counts, cancellation and shared work before materializing any hierarchy. A root consumes zero composition edges: the current hard ceilings admit eight VariantParent edges and sixteen NestedPlacement edges. The complete detached result alone can reach Scene/runtime conversion. Schema digest, capture policy, authored/actual revision evidence and canonical source commitments participate in cache and publication fences.

Qualification targets are `HoroPrefabTests`, `HoroSceneDocumentTests`, `HoroPrefabSceneCookHostTests` and `HoroFoundationJsonTests`, with the existing prefab public-header consumers. Added regressions exercise layered value/topology precedence, exact edge boundaries, permutation and lexical admission, actual native scene/template cook publication, strict stale/missing-schema rejection, source history/rebase/cancellation and allocation-failure preservation. These are test requirements, not a claim that the external draft has been built or executed.
