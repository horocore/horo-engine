# Offline GPU particle Metal family cook

`HoroVfxGpuShaderCook` is an explicit offline executable. The editor never invokes a compiler.
It requires independently supplied authenticated host catalog, detached signature, trusted publisher roots,
and approved native DXC, SPIR-V validator, SPIRV-Cross and Apple xcrun executable paths.
Observed tool hashes are not approval and no signing keys are generated by this command.

```
HoroVfxGpuShaderCook ABS-repository-root ABS-new-package-root ABS-existing-scratch \
  ABS-catalog ABS-detached-signature ABS-host-trust \
  ABS-dxc ABS-spirv-val ABS-spirv-cross ABS-xcrun
```

The output parent and scratch must already exist and be exclusively owned by the caller.
The output must be absent and outside the actual scratch directory tree, including aliases.
The `.vfx-gpu-package-` filename namespace is reserved on all hosts using ASCII case-insensitive matching.
Publication compiles both canonical sources, validates the complete compute/direct-draw family,
writes a private candidate, decodes and revalidates the written artifact/reflection pairs, then renames
that whole directory. Failures leave no final package and preserve foreign candidate directories.

The pairs are `shaders/runtime/vfx-simulation-metal.horoshdr` plus `.reflection.json`, and
`shaders/runtime/vfx-gpu-draw-metal.horoshdr` plus `.reflection.json`. The simulation artifact contains
the real `SimulateParticles` stage; the draw artifact contains real `VfxGpuVSMain` and `VfxGpuPSMain` stages.
The informational `vfx-gpu-cook-provenance.json` records actual source/output digests and authenticated
catalog/tool identities. It does not replace independent trust roots or authenticate runtime execution.
Trust roots, local executable paths and keys are never copied into the package.

Successful cooking does not prove native dispatch, pixels, asynchronous readback, Vulkan or D3D12 coverage.
